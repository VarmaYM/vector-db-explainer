Notice the contract

These systems answer identity and structure questions: retrieve this key, match these fields, join these rows, or commit these changes. A result can be checked against the condition.

Turn the question

Vector retrieval begins when the request becomes: “Which items are nearest to this query in a learned representation?”

02 / CONTRAST
Exact ≠ nearby

A predicate draws a line. Similarity draws a slope.

Exact retrieval returns records that satisfy a condition. Similarity retrieval ranks candidates by distance under a chosen model and metric. One is a gate; the other is an ordered neighborhood.

PredicateRanked candidatesMetric mattersNo automatic truth
Same catalog, two questionswatch the output change

The dangerous shortcut

A high similarity score does not prove identity, authorization, freshness, uniqueness, or correctness. It only says “nearby” within the chosen representation.

Route hard constraints

IDs, dates, numbers, joins, ACLs, transactions, and current state remain filters or source-of-truth reads. Similarity can help find candidates around them.

Checkpoint02 / 10
If a result is nearest, is it automatically the correct record?
No. It is a candidate ranked by a model and metric. Hydrate it, apply hard constraints, and validate it where correctness matters.

03 / LEXICAL SEARCH
Inverted index

Before vectors, search learned to invert.

A full-text system turns terms into posting lists: each token points to the documents containing it. It is fast, inspectable, and excellent at literal words, identifiers, and phrases.

The index can explain a match: token, field, frequency, and document length all have a visible role in lexical scoring.

What it catches

Rare product codes, quoted phrases, error messages, exact names, and identifiers can be more important than conceptual closeness. Dense embeddings may blur those details.

Keep the lexical signal

Dense retrieval is not a replacement for every text task. A hybrid system can preserve this exact-word evidence while adding paraphrase recall.

Checkpoint03 / 10
Why might a literal error code need an inverted index?
Because exact tokens matter. A semantic neighborhood can return conceptually related text while missing the precise code or phrase a user needs.

04 / REPRESENTATION
Embedding model

Meaning-ish relationships become coordinates.

The embedding model supplies the coordinates. The database stores, indexes, filters, and retrieves them.

Do not overread the picture

This 2D-like drawing is a teaching shortcut. Real vectors often have hundreds or thousands of dimensions, and their useful relationships depend on training and evaluation.

Compatible space

Queries and stored items must be encoded into a compatible space with a chosen similarity function. Changing the model can change the neighborhood.

Checkpoint04 / 10
What creates the “meaning-ish” coordinates?
The embedding model. The vector database does not invent meaning independently; it indexes the representation it is given.

05 / BASELINE
Exact search

Exact nearest neighbor: compare all.

Given a query vector, exact search evaluates every candidate under the chosen distance or similarity function, then returns the top-k. “Exact” refers to the search procedure — not to semantic truth.

Why keep this baseline?

For a small corpus, exact search may be simpler. More importantly, it tells you which neighbors were truly closest under your data, model, and metric so you can measure an ANN index against it.

Exact search ≠ exact lookup

“Exact” here means no candidates were skipped. It does not mean the embedding perfectly captured the user’s intent, or that the nearest item is authorized or current.

Checkpoint05 / 10
What does exact nearest-neighbor search compare?
Every candidate in the corpus, under the chosen metric. That makes it a useful quality baseline before approximating the search.

06 / SCALE
Approximate search

ANN skips work. You measure the trade.

Approximate nearest-neighbor indexes navigate a smaller part of the search space. More search effort can recover more true neighbors; less effort can reduce latency or resource use. There is no universal free lunch.

What ANN buys

Indexes such as HNSW-style proximity graphs and compressed approaches are important techniques, but products expose different implementations and controls. Benchmark your workload.

Recall is a product requirement

Choose a recall target and measure end-to-end latency, memory, build time, update behavior, filters, and freshness. “Approximate” is a deliberate operating point.

Checkpoint06 / 10
What happens when you lower the search budget?
Fewer nodes are explored. That may lower work or latency, but the index can miss a true neighbor, reducing recall. The real curve needs measurement.

07 / ARCHITECTURE
Derived index

A vector database is a retrieval component.

It commonly stores vectors with IDs and metadata, maintains an index, supports updates and filters, and returns nearest candidates. The canonical record, policy decision, and current fact still live elsewhere when those guarantees matter.

A vector record is a versioned projection, not the canonical fact.

Responsibilities it can own

Vector storage, nearest-neighbor indexing, top-k retrieval, metadata filtering, IDs, and operational index lifecycle. Exact API, consistency, scaling, and guarantees vary by product.

Responsibilities it should not silently absorb

Transactions, identity, authorization policy, current state, joins, aggregates, calibrated probabilities, and audit truth. Re-read those from the system designed to guarantee them.

Checkpoint07 / 10
Who decides whether this caller may see a candidate?
The policy-aware source layer. Metadata prefilters can narrow candidates, but authorization must be bound to the request and re-checked against current policy before display or action.

08 / COMBINE SIGNALS
Hybrid retrieval

Let each signal do its best job.

A practical search path often combines structured filters, lexical retrieval, and dense retrieval. Over-retrieve, merge or rerank, then hydrate and validate against the source of truth.

Why not dense-only?

Dense retrieval can find paraphrases and concepts, while lexical retrieval protects exact terms and phrases. Combining their candidate sets reduces blind spots.

Filter early, validate late

Apply safe tenant and metadata constraints before retrieval where possible; over-retrieve when filters may remove good candidates; re-check authorization and freshness before returning.

Checkpoint08 / 10
What does hybrid retrieval protect against?
Both kinds of miss: dense search may miss rare literal tokens, while lexical search may miss paraphrases. The merge still needs ranking and source validation.

10 / ARRIVE
Choose the component

The finish line is not “use vectors.” It is use the right boundary.

Vector databases are powerful retrieval components. They become fragile when asked to be the system of record, a probability oracle, an authorization engine, or the answer to every text problem.

Use a vector database when the output contract is a ranked candidate list in a learned space — then design the second stage before shipping the index.

One managed product, after the concept

Pinecone is one documented managed-product example that exposes vector indexing and retrieval options. Its product behavior is not a definition of every vector database.

The reusable decision

Source of truth + vector retrieval + deterministic or learned second stage. The vector result is a ranked candidate, never a proof that the item is correct, current, authorized, unique, safe, or anomalous.

Final checkpoint10 / 10
Complete the sentence: “A vector database is best when the output is…”
…a ranked list of candidates near a query in a learned representation. Pick another system, or a hybrid, when the output is an exact record, current fact, aggregate, policy decision, or calibrated action.

THE TAKEAWAY

Similarity is a signal, not a guarantee.

Once the question is explicit, the architecture is easier to draw: keep facts and permissions authoritative, use similarity to widen the candidate set, and make the final contract observable.

1
Name the output. Candidate list, exact record, current fact, aggregate, probability, or action?
2
Keep hard constraints hard. IDs, dates, joins, uniqueness, transactions, ACLs, and freshness do not become semantic because a vector exists.
3
Benchmark the path. Compare exact and ANN retrieval, then test authorization, deletes, updates, empty results, and final task quality.
